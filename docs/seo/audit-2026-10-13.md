# yaynyc.com: read-only SEO and data audit

Date: 2026-10-13 (America/New_York). Nothing in the site, the database or DNS was changed for this audit. No Search Console or analytics data exists yet, so nothing here describes rankings, indexing or traffic.

## How this was checked

| What | How |
|---|---|
| Stack, routes, build | Read the repository (`site/`). |
| Live server HTML | All 875 sitemap URLs fetched from the live site on 2026-10-13 (through the project database's HTTP client, since this sandbox cannot reach the site or Supabase directly). Analysed for status, canonical, title, description, h1, JSON-LD and internal links. |

## Stack and content model

- **Framework:** Astro 5, fully static (`output: static`, `build.format: file`, no trailing slash). Hosted on Cloudflare Workers static assets, built by Cloudflare Workers Builds from branch `claude/lucid-keller-2hsgwn`, root `site/`.
- **Build:** `node scripts/fetch-images.mjs && astro build && node scripts/verify-build.mjs`.
  - `fetch-images` downloads the approved, freely licensed photos from Wikimedia Commons.
  - `verify-build` is the gate. It checks isolation from HappyTLV, one h1, title, description, canonical, no `undefined`, internal links, image alt, one keyword per page in title + h1 + description, unique keyword/title/description, description length, and that the sitemap matches the pages.
- **Data:** fetched at build time from Supabase (`zqfscuwkxcoktpjhaebv`) with the publishable key; RLS decides what is public. Cleaned in `site/src/lib/data.ts` (`clean()`): no placeholder phones, no bottle prices, no rounded coordinates, no contradictory opening hours, de-duplication.
- **Routes:**

## Findings

### F1. `/parties` and `/parties/halloween` show zero events. Cause: nothing is published.

- `party_events` holds **606 upcoming nights**: 529 `draft`, 77 `review`, **0 `published`**. The public view `site_parties` filters `publish_status = 'published'` and returns 0 rows. The build therefore has nothing to render.
- This is **not** client rendering, the date filter, timezone or the schema. The server HTML has 0 party cards, `/data/parties.json` is `[]`, and the build-time cutoff (`ends_at ?? starts_at > now − 2h`) is never reached.
- **Publish blockers** (`party_publish_blockers`) on the 606:

  | Blocker | Nights |
  |---|---|
  | no copy | 603 |
  | status rescheduled | 14 |
  | age unknown | 5 |
  | venue not confirmed | 4 |
  | open source conflicts | 3 |
  | postponed | 1 |

- 3 nights have reviewed copy and no blockers, but sit in `review`: publishing is a deliberate separate step.
- Halloween: 141 upcoming candidates (70 Brooklyn, 65 Manhattan), none published.
- **Side effect to fix:** `/parties` is indexable and its title reads "NYC Parties: 0 Club Nights…". That is a thin page. `/parties/halloween` is already `noindex` (fewer than 2 nights).

### F2. "Checked Sep 2" is the real source date, not a stale build or cache.

`hh_checked` across all 742 live bars: 1 on Sep 1, **728 on Sep 2**, 13 on Sep 3, 40–42 days before this audit. No happy hour has been re-checked since import. Party records were all re-checked from DICE on Oct 13.

**Proposed freshness rules** (proposal only, nothing enforced):
1. Always show the check date; never hide it.
2. At 60+ days, a bar page shows "Checked 63 days ago: deals may have changed" in plain text, and the bar is not used as the headline of a list page ("cheapest drink…").
3. Re-check cadence: bars featured in a guide table, every 30 days; all bars, every 90 days; parties in the next 14 days, daily; later nights, weekly.
4. A bar whose source page is gone (404) or says "closed" is moved to `review`, not deleted.
5. `lastmod` in the sitemap stays the real check date (already the case).

### F8. Dates and time zones

- Server side uses `America/New_York` through `Intl` (`nyTime`, `nyDate`).
- `nightDate()` formats a date at 12:00 with a fixed −05:00 offset. That is safe for date-only display (noon never crosses midnight in EDT or EST).
- Cross-midnight nights use `night_date` (the evening the night starts), so a 10pm–4am party belongs to its first evening. The explorer's "now" logic handles happy hours past midnight.
- **Low-risk bug:** the client "Tonight / Tomorrow / Weekend" filter builds dates from the visitor's local clock at noon. For visitors in UTC+12 to +14 it can be off by a day. Fix: compute those dates in `America/New_York`.

### F9. Images

- 46 neighborhoods and a few venues/bars have photos. All are from Wikimedia Commons under CC0, PD, CC BY or CC BY-SA, with author, license and file link on the page and on `/image-credits`.
- Licenses are filtered by rule; none is marked uncertain.
- One earlier false match (a banknote for the club "3 Dollar Bill") was caught and rejected. Matching now requires a NYC place in the file data.
